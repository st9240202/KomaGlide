# KomaGlide 第一版閱讀需求

本頁記錄桌面集中書庫原型的需求與實測。0.6.0 起的主版本改用各漫畫站的 IndexedDB，安裝和重讀方式見 [README](../README.md)。

## 線上閱讀

- 在桌面 Chrome 自動辨識漫畫。讀者可以在原站向下連讀，也可以開啟覆蓋在當前分頁上的直向閱讀器。
- 同一話內自動接頁。是否自動接下一話由全域開關控制，預設關閉。
- 載入幾頁正文就快取幾頁，包含預載的圖片。從原站章節網址再次進入時，已儲存的漫畫頁必須可從本機顯示，對應圖片不得再向圖站發出請求。
- 通用辨識可在陌生網站運作。專用網站模組放在專案內，隨版本發布。若已辨識出一話、作品歸屬仍不明，照常快取，提供單話收藏；確認作品後才提供整部收藏。

## 離線與安裝

- 安裝後直接到漫畫站閱讀即可開始保存。讀者無須先開書庫、建立書籤或選取資料夾。
- 在兩個網站讀過漫畫後，關掉 Chrome、斷網再開，須能從書庫依頁序閱讀兩站已存的頁面。
- 依[共用容量決策](./adr/0001-shared-cache-budget.md)保護收藏並淘汰舊話。

## 原型前的判斷

選定的驗證路線為單一 Tampermonkey 腳本搭配靜態書庫。Chrome 可能在腳本接手頁面前就發出圖片請求。驗收分別量測重開原站時的圖片請求數，以及斷網重啟後能否讀圖。本頁下方的原型結果記錄目前達成的範圍。

## 純 Tampermonkey 方案比較（原型前）

### 重開原站時的流量

以桌面 Chrome 157 的獨立設定檔測試兩種章節 HTML。預先將同一張圖存入本機，圖站回應設為 `Cache-Control: no-store`，每種頁面各重開 Chrome 三次。伺服器按圖片路徑計數。

| 網頁載圖方式 | 圖片元素最後使用的來源 | 三次重讀的原圖請求數 |
| --- | --- | --- |
| HTML 直接給出 `img src`，頁首已註冊觀察器，看到元素就替換 | 本機 | 1、1、1 |
| HTML 只給出 `data-src`，由閱讀器查完快取才設定 `src` | 本機 | 0、0、0 |

此測試隔離 Chrome 解析與載圖行為，使用同步可讀的本機圖，未安裝 Tampermonkey。即使採用這個時序較有利的測法，畫面使用本機圖仍可能產生原圖請求。Chrome 的預載機制以及 Tampermonkey 在 Chrome MV3 上的 API 限制，使通用 userscript 無法保證任意原站網址零重抓。[Chrome 預載機制](https://web.dev/articles/preload-scanner) · [Tampermonkey 請求 API](https://www.tampermonkey.net/documentation.php?q=GM_webRequest)

離線書庫可以全程從本機取圖。對腳本自行接上的後續頁面，可以先讀快取再建立圖片元素。某個網站模組若要宣告「原網址零重抓」，須逐站驗證它能在網站載圖前接手，並包含直接開網址、重新整理與缺頁續讀；驗收時要排除瀏覽器 HTTP 快取的影響。

### 跨站書庫與容量

| 方案 | 讀者的操作與限制 |
| --- | --- |
| 單一腳本，圖片存 Tampermonkey 鍵值 | 可從不同網站讀同一份資料，但大量資料已有腳本啟動失敗的回報。能否承受 1 GiB，以及斷網重啟時從哪裡開書庫，均未驗證。[Tampermonkey 問題紀錄](https://github.com/Tampermonkey/tampermonkey/issues/1787) |
| 單一腳本，各漫畫站自行存 IndexedDB | 初次閱讀即可快取，從原站重讀時可查到該站資料。來源隔離使跨站離線讀圖與跨站整話淘汰需要另一套協調機制。[Chrome 儲存分區](https://privacysandbox.google.com/cookies/storage-partitioning) |
| 單一腳本搭配固定網址的靜態書庫 | 讀者只裝腳本。設計上，第一次在線閱讀時自動開背景書庫分頁，讓書庫預存介面、集中保存圖片。需要專案維護固定網址，讀者離線可從網址或歷史紀錄開啟。能否從兩個漫畫站自動交付圖檔，仍須用真正的 userscript 驗證。[背景分頁 API](https://www.tampermonkey.net/documentation.php?locale=en&q=GM_openInTab) |

已在另一個獨立的 Chrome 157 設定檔驗證離線冷啟動。測試頁透過 service worker 預存書庫 HTML，並將一張 68 位元組的 PNG 寫入書庫自己的 IndexedDB。完全結束 Chrome、關閉本機來源伺服器後，用同一設定檔重開書庫網址，仍可看到作品，也能直接進入先前未開過的閱讀路徑並解碼相同圖片。測試只涵蓋單一書庫來源、一張圖與重啟；兩個漫畫站的資料移交、免手動初始化與大容量負載仍待實測。

集中儲存可依已提交的圖片位元組數執行 1 GiB 上限、作品與單話收藏、整話淘汰。仍須驗證同時寫入、磁碟配額不足、暫停後復原，以及是否取得瀏覽器持久儲存授權。收藏會受到 KomaGlide 的淘汰規則保護；讀者清除瀏覽器網站資料時也會移除本機書庫。[Chrome 持久儲存說明](https://web.dev/articles/persistent-storage)

## 原型驗收

在獨立的 Chrome for Testing 153.0.8010.12 設定檔安裝官方 Tampermonkey 5.5.1，透過管理面板安裝 userscript。安裝後直接進漫畫站，書庫由腳本在背景開啟。

| 真實網站 | 存入書庫的正文 | 停用 HTTP 快取後，重開原站的正文圖請求 |
| --- | --- | --- |
| [xkcd 第 1 話](https://xkcd.com/1/) | 1 頁，24,848 B | 1 次 |
| [Pepper&Carrot 第 1 話](https://www.peppercarrot.com/en/webcomic/ep01_Potion-of-Flight.html) | 4 頁，1,196,079 B | 4 次 |

真站欄位取自瀏覽器觀察到的圖片請求。在原站開啟彈出閱讀器後，兩站共五頁都從本機顯示，閱讀器新增的圖站請求均為零。完全結束 Chrome、關閉書庫伺服器後，五頁也都能在斷網重啟的書庫中解碼並閱讀。

可控制的測試站另外在 HTTP 伺服器計數。兩站夾帶非正文圖，並提供接續章節與分頁。完全結束瀏覽器、停止全部三個伺服器，再以斷網模式重開，各測試頁的 SHA-256、解碼後寬高與閱讀順序均符合預期，離線閱讀對漫畫來源的請求數為零。彈出閱讀器、接續已快取章節、同話自動接頁及跨站保留自動跨話設定均通過測試。[整合測試](../tests/browser-smoke.cjs)

容量另於桌面 Chrome 157 測試。兩話各存入 64 頁，每頁 8 MiB，合計 1 GiB。再存第三話首圖，最舊一話的 64 頁全部淘汰，較新一話的 64 頁全部保留，新圖也成功儲存。[容量測試](../tests/library-capacity.cjs)

### 8comic 實站驗收

2026-11-22 在 EGoLite 以 Tampermonkey 執行 KomaGlide 0.1.1。從[作品目錄](https://www.8comic.com/html/23337.html)開啟《魔法少女x敗北裁判》第 1 集，書庫先存入原站已載入的 4 頁。沿原站捲到話末，書庫顯示 57 / 57 頁，圖片共 21,371,714 位元組。閱讀進度片段和配色參數共用同一筆章節。

將書庫分頁設成離線，並以無法從網路讀取的測試請求確認斷網。依原站頁碼逐一顯示及解碼 57 張本機 Blob，寬高均與原站相同，書庫對閱讀站或圖站的資源請求為零。也驗證離線直接開啟章節連結及重新整理，兩次均由 service worker 提供介面。這次驗收保留 EGoLite 的其他分頁連線。[網站模組](../src/sites/8comic.js) · [回歸測試](../tests/8comic.cjs)

同日在 EGoLite 以 KomaGlide 0.4.3 開啟目錄中的第 2.1 話（`ch=2a`）。原站只載入前幾張圖時就開啟直向閱讀器，在雙頁模式從第 1 頁翻到第 31 頁，每頁都成功顯示。切換為直向捲動後，也能用滾輪往下閱讀。書庫顯示已存 31 / 31 頁。將書庫分頁斷線並重新整理後，逐頁確認 31 張本機圖片皆可解碼，對 8comic 圖站的資源請求為零。
